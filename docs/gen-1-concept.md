# Gen-1 — лаборатория эволюционных агентов

> Реализована [модель жизни v2](life-model-v2.md): физиология, рост, два пола, поиск партнёра,
> беременность, наследование обоих родителей, память и восстановление растений.
> Ниже сохранена исходная концепция первой версии; описание бесполого размножения историческое.

## Идея

Визуальная симуляция искусственной жизни: организмы исследуют мир, ищут пищу, расходуют энергию, размножаются и передают потомкам гены с мутациями. Пользователь наблюдает эволюцию, меняет условия среды и сравнивает результаты экспериментов.

Первая версия — 2D-плоскость с видом сверху. Затем — объемная карта с рельефом, на поверхности которой живут организмы. Прогнозирование развития популяции добавляется после создания воспроизводимой симуляции.

## Стек и принципы

- TypeScript в строгом режиме, Vite, Three.js.
- Логика приложения строится на классах; интерфейсы и типы описывают данные и сообщения.
- Менеджеры используют контекстный Singleton по образцу `ContextSingleton` текущего проекта: `App.inst('main')`, `SimulationEngine.inst('simulation')`.
- Организмы, геномы и отдельные эксперименты — обычные экземпляры классов, а не Singleton.
- Расчеты мира выполняются в Web Worker. Главный поток отвечает за Three.js, интерфейс и взаимодействие пользователя.
- Модель мира не зависит от Three.js и DOM: ее можно запускать без визуализации для массовых экспериментов.
- Singleton существует отдельно в каждом потоке; общение между потоками идет через сообщения.

## Первая версия: наблюдаемая жизнь в 2D

Мир — ограниченная плоскость XZ, высота Y = 0. Камера ортографическая, направлена сверху. Организмы и пища отображаются простыми фигурами; цвет организма обозначает выбранный признак, размер — размер тела.

Начальные механики:

- Генерация пищи и стартовой популяции по заданному seed.
- Поиск пищи в радиусе восприятия, движение к ней, исследование при отсутствии цели.
- Расход энергии на жизнь, движение и восприятие; получение энергии из пищи.
- Возраст, смерть от истощения или достижения предельного возраста.
- Бесполое размножение при достаточной энергии: родитель передает часть энергии потомку и оплачивает стоимость размножения.
- Наследование генов с ограниченными случайными мутациями.

Начальные гены: скорость, радиус восприятия, размер тела, порог энергии для размножения, склонность к исследованию. У каждого признака есть допустимый диапазон и влияние на поведение или энергетическую стоимость. Единственного заранее заданного «лучшего организма» нет: результат зависит от среды.

## Математическая модель

Время симуляции дискретное, с фиксированным шагом `dt`, независимым от частоты кадров.

Пример энергетического баланса за шаг:

`E_next = E + E_food - (c_base * size + c_move * size * speed² + c_vision * radius) * dt`

Здесь `speed` — фактическая скорость, `radius` — радиус восприятия; коэффициенты и единицы задаются конфигурацией модели. Полученная энергия ограничивается вместимостью организма. Формула — начальное правило искусственного мира, которое уточняется экспериментами.

Мутация отдельного гена с вероятностью `mutationRate`:

`gene_child = clamp(gene_parent + Normal(0, sigma), min, max)`

Для разных генов используются свои масштабы `sigma`. Отбор возникает через выживание и размножение. Случайные решения принимает генератор с seed; порядок обновления сущностей фиксирован. Одинаковые настройки, seed и последовательность команд должны воспроизводить результат в пределах одной версии движка.

## Архитектура классов

| Класс | Ответственность |
| --- | --- |
| `App` | Инициализация и завершение работы приложения |
| `SceneManager` | Three.js, камера, освещение и цикл отображения |
| `WorldRenderer` | Отображение снимков мира, интерполяция, выделение организмов |
| `SimulationBridge` | Типизированные команды и ответы между UI и Worker |
| `SimulationEngine` | Фиксированный шаг, состояние запуска и порядок расчетов в Worker |
| `World` | Границы, организмы, ресурсы и состояние среды |
| `Organism` / `Genome` | Состояние организма и наследуемые параметры |
| `BehaviorSystem` | Выбор действий и движения |
| `EnergySystem` / `EvolutionSystem` | Энергия, возраст, размножение, мутации и смерть |
| `SpatialIndex` | Поиск соседей и пищи через пространственную сетку |
| `SeededRandom` | Воспроизводимые случайные числа |
| `StatisticsCollector` | Метрики популяции и история эксперимента |

Системы получают зависимости явно. Singleton применяется к менеджерам жизненного цикла, а состояние каждого эксперимента хранится в отдельном `World`.

Предлагаемая структура:

```text
src/
  app/           # App и запуск
  core/          # ContextSingleton, конфигурация, SeededRandom
  simulation/    # World, Organism, Genome, системы, SpatialIndex
  worker/        # Точка входа Worker, SimulationBridge, обработчики
  rendering/     # SceneManager, WorldRenderer, управление камерой
  ui/            # Панели управления, инспектор, графики
  shared/        # Типы команд, снимков и статистики
```

## Обмен с Worker и производительность

Главный поток отправляет команды `init`, `start`, `pause`, `step`, `setSpeed`, `reset`, `updateConfig`, `inspectOrganism`. Worker возвращает `ready`, `snapshot`, `stats`, `organismDetails`, `error`. Команды изменения мира применяются на границах шагов.

Worker — единственный владелец состояния симуляции. В UI передаются сериализуемые данные, а не экземпляры классов. Снимки содержат номер шага, время, ID и визуальные параметры сущностей. Инспектор получает подробности выбранного организма отдельно.

Начальный ориентир: 30 шагов расчета в секунду модельного времени, 10–20 снимков в секунду реального времени, отрисовка через `requestAnimationFrame`. Значения уточняются по замерам. Ускорение увеличивает число шагов, сохраняя `dt`; Worker обрабатывает их порциями, чтобы оставаться отзывчивым к командам.

Для больших популяций: `InstancedMesh`, пространственная сетка, упакованные массивы и передача `ArrayBuffer` с учетом передачи владения. Очередь снимков ограничивается: устаревшие кадры отображения можно пропускать без пропуска расчетных шагов.

## Что видит пользователь

- Карту с организмами и пищей; масштабирование и перемещение камеры.
- Запуск, паузу, один шаг, скорость, сброс и seed эксперимента.
- Выделение организма: ID, родитель, поколение, возраст, энергия, гены, текущее действие.
- Дополнительные слои: радиус восприятия, направление движения, окраска по гену или энергии.
- Графики численности, рождений и смертей, средней энергии и распределения генов.
- Настройки ресурсов, начальной популяции и мутаций; указание, какие изменения требуют перезапуска.

## Развитие до 3D и прогнозирования

1. **Основа:** Vite + TypeScript, классы и Singleton, сцена, Worker, протокол сообщений, фиксированный шаг и seed.
2. **Жизнь в 2D:** питание, движение, энергия, размножение, мутации, инспектор и базовые графики.
3. **Эксперименты:** препятствия, разные зоны ресурсов, сезонность, сохранение состояния и сравнение запусков.
4. **3D-карта:** перспективная камера, рельеф `heightAt(x, z)`, движение по поверхности, стоимость подъема и проходимость. Расчет высот и ограничений остается в Worker; отображение строится по тем же данным. Полноценное движение в объеме — отдельный последующий этап.
5. **Прогнозирование:** многократное продолжение сохраненного состояния с независимыми потоками будущей случайности. Оценка вероятности вымирания, диапазона численности и распространения признаков на заданном горизонте. Результаты относятся к правилам модели.

Сохранение включает версию модели, конфигурацию, текущий шаг, сущности, состояние среды и генератора случайных чисел. Одного начального seed недостаточно для точного продолжения из середины эксперимента.

## Готовность первой версии

Пользователь запускает мир и визуально наблюдает несколько поколений, может поставить симуляцию на паузу, выполнить один шаг и изучить организм. Графики отражают изменения популяции. При одинаковом seed и настройках повторный запуск дает тот же результат; изменение скорости отображения не меняет исход при одинаковом числе расчетных шагов.

Проверки: воспроизводимость, допустимые диапазоны генов, энергетический баланс размножения, корректность рождения/удаления сущностей и соответствие состояния Worker визуализации. Начальная цель для замеров — 1 000 организмов; фактические FPS и время шага фиксируются вместе с параметрами устройства.
